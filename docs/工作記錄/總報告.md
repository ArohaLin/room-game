# 《回家的鑰匙》工作室總報告(總監彙整)

> 五人工作室(總監／編劇／美工／程式開發人員／測試人員)依流程協作完成的成品。
> 本報告摘要「誰、在哪個階段、做了什麼」;各角色詳細工作記錄見同目錄各檔。

## 一、成品
- 溫馨家庭密室解謎網頁遊戲《回家的鑰匙》,單頁、純前端、離線可玩、無音效。
- 12 房間 × 4 樓層、10 道謎題、完整短篇劇情(親子/家庭團聚,Happy ending)、適合 9-12 歲。
- 入口:`index.html`(以 `python3 -m http.server` 起本機伺服器開啟)。

## 二、各階段 × 各角色做了什麼

### 立項(總監)
- 產出創意 Brief:一句話定位、8 條設計原則、難度節奏、給編劇/美工的指示、9 條驗收標準、7 個命名候選。
- 詳:`立項-總監.md`、`docs/00-創意Brief.md`

### 設計(編劇 ‖ 美工 平行)
- 編劇:完整劇情《回家的鑰匙》、5 位角色、5 段敘事、P1–P10 謎題與鎖鑰依賴圖、漸進提示、Happy ending。詳:`設計-編劇.md`、`docs/01`、`docs/02`
- 美工:溫馨手繪風格指南、10 色調色盤、12 房間美術規格、四大 UI 元件、純前端繪製可行性。詳:`設計-美工.md`、`docs/03`

### 交叉對齊(編劇↔美工互評一輪 → 總監裁決)
- 編劇評美工、美工評編劇各提一輪意見;總監裁決定案並下達雙方調整清單(討論上限 2 輪,達標即裁決,防發散)。
- 詳:`交叉對齊-編劇評美工.md`、`交叉對齊-美工評編劇.md`、`交叉對齊-總監裁決.md`

### 審查定案(總監)
- 一致性檢查(DAG/線索可得/無 soft-lock/可通關/題數/年齡)並凍結 GDD。詳:`審查定案-總監.md`、`docs/04`

### 設計試玩(測試人員,冷啟動·看不到解答)
- 模擬真實玩家試解,**揪出 6 項公平性問題**:P8 顏色鏈斷裂(黃綠無來源)、P1 門矛盾、P2「6 號」沒用到、P7「337」用過即丟、P6「左」字矛盾、P8 一題多解;並建議加偵探筆記。詳:`設計試玩-測試人員.md`、`docs/05`

### 最終定案修訂(總監)
- 將上述發現逐一裁決為 D1–D8,凍結「公平可通關版」(鑰匙制開門、四色卡補完、順序唯一解 2615、6 號改情感線索並結局回收、337 揭示規則、移除「左」字、偵探筆記、三重編碼無障礙)。詳:`定案修訂-總監.md`、`docs/06`

### 實作(程式開發人員)
- 模組化純前端(data/art/game),完成 12 房間 SVG、10 謎題互動、敘事/結局、偵探筆記、提示、物品欄、樓層導覽、存檔。詳:`實作-程式開發人員.md`

### 本機測試(測試人員)
- 三層測試全通過(語法、全流程狀態機、各謎題真實 UI 答案判定 + 視覺);實機回測抓出並修正 3 個程式 bug(開門 need 誤判、P2 越權解鎖、P4 開局即解)。詳:`本機測試-測試人員.md`

## 三、品質結論
- 全流程實機可通關、無 soft-lock、無 console 錯誤;謎題公平單一解,線索皆遊戲內可得;風格、年齡、無恐怖、Happy ending 皆達 Brief 驗收標準。
- **多 agent 價值佐證**:獨立、資訊不對稱的測試人員在「看不到解答」下抓出 6 項設計者自身難以察覺的公平性破綻,經總監裁決修訂後才實作——避免把有缺陷的設計直接做成成品。
